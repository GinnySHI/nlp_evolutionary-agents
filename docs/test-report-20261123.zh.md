## 4. 失败模式

### 4.1 本次运行中发现并修复的平台缺陷

**推理 token 饿死输出 —— 影响最大的一个。** 两个获准主干都是推理模型，思考 token 计入 `max_tokens`。在配置的 8192 上限下，`deepseek-v4-pro` **把 8192 token 全部花在推理上，一个字都没有输出**（`finish_reason: length`）。引擎正确地没有执行任何动作，这一回合就此浪费。此前被归因于「智能体效率低」的「120 轮耗尽」失败，推理预算是一个已观测到的失败机制，但没有对照重跑可以证明它解释了此前所有预算耗尽。

| 设置 | 推理 token | 实际输出 | 延迟 |
|---|---|---|---|
| 默认，上限 8192 | 8192 | 无 | — |
| 默认，上限 32768 | 16904 | 5101 字符 | 166 秒 |
| `reasoning_effort: low`，上限 16384 | 1376 | 4754 字符 | 23 秒 |

**非动作响应。** 在三个会话中抽样的 37 次无效响应里，**22 次是裸 JSON 数据数组**（房间记录、搜索结果行）而非动作。另有若干是在合法对象后追加解说文字，或泄漏内部 `DSML` 工具调用标记。解析器现在取第一个完整对象并丢弃非 JSON 残余 —— 但仍然拒绝未闭合的对象，也仍然拒绝在两个可解析对象之间替模型做选择。恢复次数计入 `recovered_responses` 并写入审计。本轮补验前完成的五项任务**共有 38 次响应被恢复**（5 + 9 + 2 + 6 + 16）；此前总数 24 漏计了 fund-2 的 14 次恢复。加上本次 software-2 的 9 次，六项最终合计为 **47 次**。恢复避免了浪费这些回合，但仅凭计数不能证明每项任务原本都会失败。本轮还修复了解析歧义：余文中的非法花括号文本不能再掩盖第二个完整对象。

**HTTP 402 被当成致命错误。** 余额耗尽被归类为配置错误并直接终止任务。fund-2 的第一次尝试正因此被杀，而当时已有两个子任务通过同伴验收、费用也已实际发生。现在它与 429/5xx 一样进入暂停路径 —— 已验收的工作得以保留，人类充值后回复即可恢复 —— 但刻意不重试，因为余额不会自行恢复。401 仍为硬错误。

### 4.3 有效运作的部分

沙箱是真实的，不是名义上的：QA 尝试绑定本地回环套接字时被拒绝，返回 `PermissionError: [Errno 1] Operation not permitted`，QA 随即改为用伪造流直接调用处理器方法。智能体自身的测试也是实质性的而非走过场 —— dev 的自测发现了 `server.py` 中真实的 `BookingStore.__init__()` 签名错误；并发测试显示 20 个线程争抢同一时段时，恰好产生 1 个预订和 19 次冲突。

同伴评审确实改变了产出，而非盖章放行。fund-2 中风险经理迫使团队撤回无法溯源的「210 亿美元 GlobalFoundries」数字，并补充了集中度与拥挤度风险；研究分析师也在意识到 SIA 月度数据是三个月移动平均、不可直接相加之后，主动撤回了自己先前提出的「对账缺口」结论。

**延续性的证据：**

- 基金团队第一个任务的研究使用了临时性的「NOT VERIFIED」标注。第二个任务中，同一位分析师把它正式化为四级标注体系（`[E]` 证据 / `[J]` 判断 / `[NV]` 未核实 / `[D]` 推导）并附带来源台账，这些标注一路传递到幻灯片的每一页。这套纪律被继承并强化了。
- 新闻团队第一个任务的文章引入了「我们无法核实的内容」一节；第二个任务的事实核查沿用同一约定，把 OpenAI 分类器页面正文与 Turnitin 页面（HTTP 403）列为未核实，而不是略去不提。
- 基金团队保留了风险复核的习惯：第一个任务的风险经理复算了回撤算术，第二个任务的风险经理则促成了两处实质性修正。

**反面证据，明确写出：** 记忆与工作区的延续同样**造成了**一次失败。新闻团队记者残留自第一个任务的 `research_notes.md` 是其第二个任务陷入协议循环的原因之一。持久化并非一律有益，本次运行提供了一个明确的反例。

这些只是提示性的，不是结论性的。每个场景仅 n=2 个任务，且没有对照消融实验（同样任务在关闭记忆下重跑），因此这些观察与「记忆有帮助」相容，但无法把记忆的作用与模型自身的上下文推理分离开。

## 6. 有效性威胁

1. **本次测量跨越多个代码版本。** 运行中的进程持有较早的解析器，而每次新的 `evo respond` 都会加载补丁后的代码。先前分界点记录在 `code-revision-B.json`。本轮解析器修复与配置更新的前后 SHA-256 记录在 [`revision-followup.json`](../reports/course-deepseek-20261123/revision-followup.json)；保存该补丁时 software-2 已在加载上一版引擎的进程中运行。
2. **software-2 与 fund-2 并非冷启动。** 它们的首次尝试被 HTTP 402 杀死，在团队工作区留下了 `analytics.py` 与 `semis_research.md`。这些被保留下来 —— 课程场景本就要求团队延续既有上下文 —— 因此其回合数低估了从零开始的成本。
3. **逐任务 token 计数被低估**（见 §2.3）。
4. **浏览器与服务端分别验收。** 本轮使用 bundled Node 和 Chrome 144 做真实浏览器交互；Python 后端在 Seatbelt 中用内存请求派发验收。仪表盘浏览器使用这些真实 handler 响应，没有在沙箱中打开 HTTP 监听端口。这不能证明部署环境、多人网络访问或所有浏览器兼容性。
5. **开放性任务需要人工评分。** 评分标准检查事实可溯源性与结构性要求，无法评判编辑质量或投资推理水平。
6. **每项任务 n=1。** 没有重复试验，因此本报告的任何数字都不支持置信区间。
