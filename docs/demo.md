# 展示流程建议

1. 运行 `./run.sh doctor`，解释指定的 HKGAI 模型和隔离后端。
2. 运行 `./run.sh init demo --scenario software`，展示四位成员的角色。
3. 运行 `./run.sh chat demo`，提交一个范围适合现场演示的小任务，观察模型自行委派和交接。
4. 遇到需求问题时现场回答。遇到执行/删除/提交等操作，展示具体文件和参数后批准或拒绝。
5. 使用 `/dm lead ...` 展示私聊，再返回群聊，说明私聊内容未广播。
6. 使用 `/status` 展示任务审核、耗时与完成状态。打开工作区查看实际产物。
7. 在同一个 session 提交后续任务，展示文件与记忆复用。对比各成员的 `memories` 及前后指标。
8. 运行自动化测试和小型评测报告，说明同伴审核与独立验收的区别、未验证边界和失败修复。

示例中的新 session 名称应避免与现有会话重名。`run --steps N` 可追加预算；不要为了展示绕过真人审批。软件课程任务还需要预留真正运行与修复的时间。

提交时需整理团队真实开发记录、架构说明、测试集结果和展示材料。Git 提交应体现每位成员的实际工作；已有自动生成代码不能代替后续真实协作贡献。
